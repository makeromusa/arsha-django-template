Mastering M-Pesa Daraja 2.0 API with Django in Kenya

Asman Makero Musa

Founder & CEO, Fahari Digital
Oct 25, 2026 • 18 Comments

Integrating mobile money into your application is essential for doing business in Kenya. Over 90% of online consumer transactions in Nairobi and across the country happen through Safaricom M-Pesa.

At Fahari Digital, we build high-volume fintech and e-commerce platforms using Python and Django. In this guide, we break down the architectural steps required to integrate Safaricom's Daraja 2.0 STK Push (Lipa na M-Pesa Online) with asynchronous callback handling.

1. Generating OAuth Tokens Securely

Safaricom requires OAuth 1.0/2.0 authentication before sending any transaction request. Best practices include caching tokens in Redis or Django memory cache to prevent redundant auth calls:

  • Store Consumer Key and Secret in environment variables (never in git)
  • Cache access tokens with a 50-minute TTL (tokens expire in 3599 seconds)
  • Handle auto-renewal on 401 response codes gracefully

Core Best Practices

  • Asynchronous Celery tasks for handling incoming webhook callbacks
  • IP whitelisting for Safaricom gateway callback endpoints
  • Automatic fallback to SMS verification for slow networks

2. Handling Real-Time STK Callbacks

The biggest pitfall for Kenyan developers is synchronous callback processing. Safaricom expects a 200 OK within 5 seconds. Save the payload immediately, respond with 200, and process the fulfillment logic in a background worker.

"Building technology in Kenya taught us that reliability under real-world network conditions is the true benchmark of good engineering."

Asman Makero Musa, Fahari Digital Nairobi

Conclusion

With proper error handling, idempotency keys, and transaction reconciliation, your Django app will provide instantaneous, rock-solid checkout experiences for millions of Kenyan consumers.
